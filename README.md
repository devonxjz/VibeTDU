# VibeTDU - Virtual Chemistry Lab

## 🔬 About the Project

**VibeTDU (Virtual Chemistry Lab)** is an interactive, web-based platform that simulates real-world chemistry experiments. Designed for educational purposes and curiosity-driven exploration, it provides a safe virtual environment where users can drag, drop, and mix various chemicals to observe reactions in real-time. 

The application goes beyond simple visual simulations by integrating external chemical databases (PubChem, Cactus, OPSIN) for accurate chemical resolution and featuring an intelligent AI assistant (powered by Google Gemini) to explain chemical phenomena, such as color changes, precipitates, and gas formation, in natural language (Vietnamese).

## ✨ Features

* **Interactive Lab Interface:** Intuitive drag-and-drop (`@dnd-kit`) interface for handling test tubes, beakers, and chemical substances.
* **Real-time Reaction Simulation:** Mix chemicals and instantly see visual feedback such as `GAS_BUBBLE`, `PRECIPITATE`, `COLOR_CHANGE`, `HEAT`, and `EXPLOSION`.
* **Dynamic Chemical Resolution:** Automatically resolves and normalizes chemical names and formulas (e.g., "NaOH" to "sodium hydroxide") using a multi-layered fallback strategy (DB Cache → PubChem → Cactus → OPSIN).
* **AI Chatbot Integration:** Embedded Google Gemini AI assistant that contextualizes current reactions and answers open-ended chemistry questions.
* **Experiment Logging:** Tracks and logs all user actions and reactions per session for auditing and educational review.
* **Responsive & Premium UI:** Built with Radix UI, Framer Motion, and Tailwind CSS for a highly engaging, modern glassmorphic and accessible user experience.

## 🌳 B-Tree Architecture

VibeTDU leverages a **B-Tree Architecture** at its core data layer. 
* **Database Indexing:** Our underlying PostgreSQL database heavily utilizes B-Tree indexes to ensure extremely low-latency lookups for the chemical registry and experiment logs. When dynamically resolving chemical strings, the B-Tree index allows O(log n) search complexity, which is crucial for the real-time responsiveness of the drag-and-drop UI.
* **Hierarchical State:** On the application side, chemical relationships and reaction trees can be modeled conceptually as a hierarchical structure, allowing the system to quickly traverse reactant-product mappings before calling out to the AI or external APIs.

## 📡 Detailed API Endpoints

The backend exposes a comprehensive set of RESTful APIs. You can view the full Swagger UI at `/swagger-ui.html` when running the backend.

### 1. Lab Operations
* **`GET /api/health`**
  * **Description:** Health check to verify backend status.
  * **Response:** `{ "status": "ok", "service": "virtual-chemistry-lab-backend" }`

* **`POST /api/lab/mix`**
  * **Description:** The core simulation endpoint. Simulates a reaction when pouring from a source vessel to a target vessel.
  * **Payload:** `MixRequest` containing `sessionCode`, `sourceVesselId`, `targetVesselId`, and the contents of both vessels.
  * **Response:** Returns reaction details including `effectType` (e.g., `PRECIPITATE`, `EXPLOSION`).

### 2. Chemical Resolution
* **`GET /api/chemicals/resolve?query={chemical_name}`**
  * **Description:** Normalizes and fetches chemical metadata (SMILES, InChI, canonical name).
  * **Example:** `/api/chemicals/resolve?query=H2SO4` returns "Sulfuric acid" and its structural data.

### 3. AI Assistant
* **`POST /api/ai/ask`**
  * **Description:** Asks a specific question based on a reaction context.
  * **Payload:** `AiAskRequest` (sessionCode, reactionContext, question).
  * **Response:** Vietnamese explanation generated by Gemini AI.

* **`POST /api/ai/chat`**
  * **Description:** Continues a conversational thread with the AI assistant.
  * **Payload:** `AiChatRequest` containing message history and context.

### 4. Session Management
* **`GET /api/session/{sessionCode}/logs`**
  * **Description:** Retrieves the chronological log of all experiment actions in a specific session.
* **`POST /api/session/reset`**
  * **Description:** Resets the experiment session, marking previous logs for audit while clearing the active state.
